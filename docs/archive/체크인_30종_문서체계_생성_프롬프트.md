# 체크인 30종 문서 체계 최초 생성

> 이 프롬프트를 Claude Code에 입력하면 프로젝트 전체를 분석하고 /docs 폴더에 30종 문서를 생성한다.
> 한 번에 30종을 다 만들 수 없으니 3단계로 나눈다.
> Phase 1 완료 확인 → Phase 2 → Phase 3 순서로 진행.

---

## Phase 1: 프로젝트 분석 + 핵심 5종 생성

```
프로젝트 전체 파일 구조를 분석하고, /docs 폴더를 만들어서 핵심 문서 5개를 생성해줘.

### 분석할 것:
1. 전체 폴더/파일 구조 (tree 형태로 파악)
2. package.json에서 기술 스택, 의존성 확인
3. DB 관련 파일 (prisma schema, migration, models 등) 전부 읽기
4. 라우팅 파일 전부 읽기 (pages/, app/, routes 등)
5. 환경변수 파일 (.env, .env.example 등)
6. 주요 컴포넌트 파일 훑어보기

### 생성할 문서 5개:

#### 1. /docs/CLAUDE.md (프로젝트 헌법)
내용:
- 프로젝트명: 체크인(Check-In) — AI 건설 분쟁 예방 플랫폼
- 기술 스택 (프레임워크, 언어, DB, ORM, 스타일링 등 — 실제 코드에서 확인한 것만)
- 폴더 구조 규칙 (현재 구조 기반으로 정리)
- 코딩 컨벤션 (현재 코드에서 패턴 추출: 네이밍, 파일 구조, import 순서 등)
- 금지사항: console.log 남기지 않기, any 타입 사용 금지, 인라인 스타일 금지 (현재 코드 패턴에 맞게 조정)
- 커밋 메시지 규칙: feat/fix/refactor/docs 접두어
- 작업 시 반드시 참조할 문서 목록 (/docs 하위 30종 목록과 각각 언제 참조하는지)
- 한국어 주석 사용

#### 2. /docs/SCHEMA.md (DB 스키마)
내용:
- 전체 테이블 목록
- 각 테이블: 컬럼명, 타입, nullable, default, 설명(한국어)
- 테이블 간 관계 (1:N, N:M 등)
- 인덱스 목록
- enum 타입 정의
- ERD를 mermaid 문법으로 작성

#### 3. /docs/ARCHITECTURE.md (시스템 구조도)
내용:
- 전체 아키텍처 다이어그램 (mermaid로)
- 프론트엔드 구조 (프레임워크, 렌더링 방식 SSR/CSR/SSG)
- 백엔드 구조 (API 라우팅, 미들웨어 체인)
- DB 연결 방식
- 외부 서비스 연동 (카카오 로그인, 파일 스토리지 등)
- 배포 구조 (현재 로컬 기준 + 프로덕션 예상)

#### 4. /docs/BUILDER_SPEC.md (기능 명세)
내용:
- 현재 구현 완료된 기능 목록 (코드에서 확인)
- 각 기능별: 기능명, 설명, 관련 페이지, 관련 API, 관련 DB 테이블, 완성도(완료/진행중/미구현)
- 미구현이지만 코드에 TODO/FIXME로 남겨진 것들
- 랜딩페이지에 소개된 기능 vs 실제 구현된 기능 비교

#### 5. /docs/BUSINESS_LOGIC.md (비즈니스 로직)
내용:
- GO/NO-GO 판정 알고리즘 (코드에서 추출)
- 리스크 점수 계산 공식 (코드에서 추출)
- 하자담보 기간 자동 계산 로직
- 12개 법령별 체크 조건 (코드에서 추출, 없으면 랜딩페이지 내용 기반으로 구조만)
- 체크리스트 자동 판정 로직

### 규칙:
- 추측하지 마. 코드에 실제로 있는 것만 문서화해.
- 코드에 없는 기능은 "미구현"으로 표기.
- 각 문서 상단에 "최종 업데이트: [날짜]" 표기.
- 각 문서 하단에 "관련 문서" 섹션으로 다른 문서 참조 링크.
```

## Phase 2: 실행 레벨 10종 생성

```
/docs 폴더에 이미 생성된 Phase 1 문서 5개(CLAUDE.md, SCHEMA.md, ARCHITECTURE.md, BUILDER_SPEC.md, BUSINESS_LOGIC.md)를 참조하면서, 추가 문서 10개를 생성해줘.

#### 6. /docs/API_SPEC.md (API 엔드포인트)
- 전체 API 엔드포인트 목록 (코드에서 추출)
- 각 엔드포인트: HTTP 메서드, URL, 요청 파라미터, 응답 형식, 인증 필요 여부, 에러 코드
- 미구현 API는 "미구현"으로 표기

#### 7. /docs/ROUTES.md (라우트 맵)
- 전체 페이지 URL 목록
- 각 라우트: URL 패턴, 렌더되는 컴포넌트, 인증 필요 여부, 동적 파라미터
- 리다이렉트 규칙 (로그인 안 한 상태에서 접근 시 등)

#### 8. /docs/COMPONENTS.md (컴포넌트 트리)
- 공통 컴포넌트 목록 (Button, Modal, Card, Input 등)
- 페이지별 컴포넌트 계층 구조 (트리 형태)
- 각 컴포넌트: props, 사용 위치, 설명

#### 9. /docs/STATE.md (상태 관리)
- 전역 상태 구조 (Context, Redux, Zustand 등 — 실제 사용하는 것)
- 각 상태: 이름, 타입, 초기값, 어디서 업데이트되는지
- 데이터 fetch 패턴 (SWR, React Query, useEffect 등)
- 캐싱 전략

#### 10. /docs/ENV.md (환경변수)
- 전체 환경변수 목록 (.env에서 추출)
- 각 변수: 이름, 설명, 예시값(실제 값은 절대 포함하지 마), 필수 여부
- 개발/프로덕션 분기 조건

#### 11. /docs/STYLE_GUIDE.md (디자인 토큰)
- 색상 팔레트 (코드에서 추출: 주황 #E8913A, 다크 배경 등)
- 폰트 패밀리, 사이즈 체계
- 간격(spacing) 체계
- border-radius 규칙
- 그림자(shadow) 규칙
- 다크모드 컬러 매핑
- 컴포넌트별 스타일 패턴

#### 12. /docs/LAW_ENGINE.md (법령 룰 엔진)
- 12개 법령 목록과 각 법령의 조문 번호
- 각 법령별: 적용 조건, 판정 기준, 위반 시 액션
- 조건-판정-액션 매핑 테이블
- 코드에 구현된 룰 vs 미구현 룰 구분

#### 13. /docs/DATA_FLOW.md (데이터 흐름)
- 핵심 플로우 3개를 다이어그램으로:
  1. 사진 업로드 → AI 분석 → 증거 저장 플로우
  2. 체크리스트 작성 → 리스크 점수 계산 → 알림 플로우
  3. 하자담보 등록 → 기간 계산 → 만료 알림 플로우
- 각 단계에서 어떤 API 호출, 어떤 테이블 저장, 어떤 상태 업데이트되는지

#### 14. /docs/ERROR_HANDLING.md (에러 처리)
- 에러 코드 체계 (코드에서 추출)
- 프론트엔드 에러 표시 방식 (토스트, 모달, 인라인 등)
- API 에러 응답 형식
- 에러 로깅 방식

#### 15. /docs/GLOSSARY.md (용어 사전)
- 건설업 전문용어: 하자담보기간, 수급인, 도급인, 감리, 준공, 시공, 감리 등
- Check-In 내부 용어: GO/NO-GO, 리스크 점수, 증빙 패키지, 법정용 PDF 등
- 각 용어: 한국어명, 영문명(코드에서 사용하는 변수명), 정의
- 코드에서 사용하는 변수/함수명과 매핑

### 규칙:
- Phase 1 문서와 일관성 유지. 용어, 형식, 표기법 통일.
- 코드에 없는 건 "미구현"으로 표기.
- 각 문서 상단에 "최종 업데이트: [날짜]" 표기.
```

## Phase 3: 확장 레벨 15종 생성

```
/docs 폴더의 기존 15개 문서를 참조하면서, 나머지 15개 문서를 생성해줘.

#### 16. /docs/TESTING.md (테스트 전략)
- 현재 테스트 프레임워크 (있으면)
- 핵심 테스트 케이스 목록 (리스크 점수 계산 정확성, 법령 판정 정확성, 하자담보 기간 계산 등)
- 단위/통합/E2E 범위 정의
- 테스트 실행 명령어

#### 17. /docs/DEPLOY.md (배포)
- 현재 로컬 실행 방법 (npm run dev 등)
- Docker 설정 (있으면)
- 프로덕션 배포 예상 구조
- 도메인, SSL 계획

#### 18. /docs/SECURITY.md (보안)
- 인증/인가 체계 (JWT, 세션, OAuth)
- 비밀번호 해싱 방식
- 파일 업로드 검증 규칙
- SHA-256 해시 생성 규칙 (증거 무결성)
- API rate limiting
- CORS 설정

#### 19. /docs/MIGRATION.md (DB 마이그레이션)
- 현재 마이그레이션 이력
- 마이그레이션 실행 명령어
- 롤백 방법

#### 20. /docs/ROADMAP.md (로드맵)
- Phase 1: MVP (현재) — 기본 체크리스트, 사진 업로드, 리스크 점수
- Phase 2: 정식 런칭 — 결제, 알림, 리포트
- Phase 3: AI 고도화 — 자동 판정 정확도 향상, 예측 모델
- Phase 4: 로봇 연동 — 휴머노이드 로봇 건설 현장 투입 시 체크인이 두뇌 역할
- 각 Phase별 기능 목록과 예상 일정

#### 21. /docs/PERMISSIONS.md (권한 체계)
- 역할 정의: 발주자, 시공사, 감리원, 관리자
- 역할별 접근 가능 페이지, API, 데이터
- 권한 체크 로직 위치 (미들웨어, 컴포넌트 등)

#### 22. /docs/NOTIFICATION.md (알림 시스템)
- 알림 종류: 하자담보 만료, 리스크 급등, 법령 위반, 체크리스트 미완료 등
- 알림 채널: 앱 내 알림, 카카오 알림톡, 이메일
- 발송 조건, 빈도 제한
- 알림 템플릿

#### 23. /docs/FILE_SYSTEM.md (파일 관리)
- 사진 업로드 규격 (최대 용량, 포맷, 리사이징)
- 저장 경로 체계
- 메타데이터 추출 (EXIF GPS, 촬영시간)
- SHA-256 해시 생성 시점
- 썸네일 생성 규칙

#### 24. /docs/PDF_REPORT.md (리포트 생성)
- 법정 제출용 증거 패키지 레이아웃
- 포함 항목: 사진, 타임스탬프, 해시값, 법령 근거
- 일간/주간/월간 리포트 형식
- PDF 생성 라이브러리

#### 25. /docs/OFFLINE_SYNC.md (오프라인 동기화)
- 오프라인 저장 방식
- 동기화 충돌 해결 규칙
- 큐 관리
- 재시도 로직

#### 26. /docs/ANALYTICS.md (분석/추적)
- 추적 이벤트 목록 (페이지뷰, 기능 사용 등)
- 핵심 지표: DAU, 체크리스트 완료율, 리스크 점수 분포
- 전환 퍼널 정의

#### 27. /docs/INTEGRATION.md (외부 연동)
- 카카오/네이버/구글 OAuth 플로우
- 카카오 알림톡 API
- 향후 연동 예정: 공공데이터 포털, 국가법령정보센터 API, 기상청 API

#### 28. /docs/CHECKLIST_ENGINE.md (체크리스트 엔진)
- 526개 체크리스트 항목 카테고리 구조
- 업종별 필터링 로직
- 필수/선택 구분 기준
- AI 자동 체크 판정 기준
- 커스텀 체크리스트 생성 규칙

#### 29. /docs/CHANGELOG.md (변경 이력)
- 현재까지의 주요 변경 이력 (git log에서 추출)
- 형식: [날짜] [카테고리] 변경 내용
- 카테고리: feat, fix, refactor, docs, style, deploy
- 이후 모든 작업 시 이 파일에 기록 추가할 것

#### 30. /docs/PROMPT_LIBRARY.md (프롬프트 라이브러리)
- 상황별 Claude Code 프롬프트 템플릿:
  - 새 페이지 추가할 때
  - 새 API 엔드포인트 추가할 때
  - DB 테이블 추가/수정할 때
  - 버그 수정할 때
  - 리팩토링할 때
  - UI 컴포넌트 만들 때
  - 테스트 작성할 때
- 각 템플릿에 "참조할 문서" 명시

### 규칙:
- 기존 15개 문서와 일관성 유지.
- 현재 코드에 구현되지 않은 기능은 "설계 단계" 또는 "미구현"으로 표기하고, 구현 시 참고할 구조만 잡아둬.
- 각 문서 상단에 "최종 업데이트: [날짜]" 표기.
- CLAUDE.md의 "작업 시 참조할 문서 목록" 섹션을 30종 전체 반영해서 업데이트해줘.
```
