====================================
작업 A: Supabase에 법령 테이블 생성
====================================

Supabase SQL Editor 또는 마이그레이션으로 실행:

laws 테이블:
- id: uuid, PK, default gen_random_uuid()
- code: varchar(50), unique, NOT NULL — 예: 'CONST_BASIC_28'
- name: varchar(200), NOT NULL — 예: '건설산업기본법'
- article: varchar(100), NOT NULL — 예: '제28조'
- title: varchar(300), NOT NULL — 예: '하자담보책임'
- description: text, NOT NULL
- check_conditions: jsonb, NOT NULL — 자동 체크 조건
- violation_action: text, NOT NULL — 미충족 시 권장 조치 메시지
- risk_weight: decimal(3,2), NOT NULL — 리스크 가중치
- category: varchar(50), NOT NULL — safety/quality/contract/dispute/warranty
- is_active: boolean, default true
- sort_order: integer, NOT NULL

law_checks 테이블:
- id: uuid, PK, default gen_random_uuid()
- project_id: uuid, FK → projects(id), NOT NULL
- law_id: uuid, FK → laws(id), NOT NULL
- status: varchar(20), NOT NULL, default 'pending' — compliant/violated/not_applicable/pending
- details: jsonb — 판정 근거
- checked_at: timestamp, default now()
- checked_by: varchar(20), NOT NULL, default 'system' — system/ai/manual

인덱스:
- law_checks(project_id)
- law_checks(project_id, law_id) UNIQUE — 프로젝트당 법령별 1건
- law_checks(status)

====================================
작업 C: 법령 체크 서비스 구현
====================================

법령 룰 엔진 서비스 파일 생성 (프로젝트 구조에 맞는 위치).

1. checkAllLaws(projectId) 함수:
   - Supabase에서 laws 테이블 조회 (is_active=true)
   - 각 법령마다 checkSingleLaw(projectId, law) 실행
   - 결과를 law_checks에 upsert (project_id + law_id 기준)
   - 전체 완료 후 기존 리스크 점수 재계산 함수 호출

2. checkSingleLaw(projectId, law) 함수:
   law.check_conditions.type에 따라 분기:

   "warranty_exists":
   → warranties 테이블에서 project_id로 조회
   → 1건 이상 있으면 compliant, 없으면 violated

   "checklist_progress":
   → checklists 테이블에서 project_id로 조회, 전체 진행률 확인
   → min_progress% 이상이면 compliant, 미만이면 violated
   → 체크리스트 자체가 없으면 violated

   "warranty_duration":
   → warranties의 duration_years가 공종별 법정 기준 이상인지
   → 하나라도 미달이면 violated, 전부 충족이면 compliant
   → 하자담보 없으면 not_applicable

   "budget_check":
   → 현재 하도급 데이터가 없으면 not_applicable

   "photo_category_exists":
   → photos 테이블에서 required_category에 해당하는 사진 존재 여부
   → 0개면 violated, 1개 이상이면 compliant

   "evidence_ready":
   → 프로젝트 risk_score가 risk_threshold 이상인지 확인
   → 미만이면 not_applicable
   → 이상인데 is_evidence=true 사진이 min_evidence 미만이면 violated

   "project_type_check":
   → 프로젝트 type이 applicable_types에 포함되는지
   → 미포함이면 not_applicable
   → 포함인데 관련 체크리스트 미완료면 violated

   "hash_check":
   → photos 중 sha256_hash가 null인 사진이 있는지
   → null 존재하면 violated, 전부 있으면 compliant
   → 사진 0개면 not_applicable

   "manual_check":
   → 자동 체크 불가 → pending

   "checklist_category_check":
   → target_category에 해당하는 체크리스트 완료율 확인
   → min_completion% 이상이면 compliant, 미만이면 violated
   → 해당 카테고리 체크리스트 없으면 not_applicable

   "completion_check":
   → 프로젝트 status가 completed인 경우만 적용
   → completed인데 검사 체크리스트 미완료면 violated
   → completed가 아니면 pending

   "merkle_check":
   → 증거 사진(is_evidence=true) 중 sha256_hash가 null이거나 merkle_root가 null인 게 있는지
   → 있으면 violated, 전부 있으면 compliant
   → 증거 사진 0개면 not_applicable

3. 각 판정 결과를 law_checks에 upsert:
   - status: compliant/violated/not_applicable/pending
   - details: {"reason": "하자담보 미등록", "checked_items": 0, "required": 1} 형태로 판정 근거 저장
   - checked_at: 현재 시각
   - checked_by: 'system'

4. Fp 점수 계산에 법령 엔진 결과 반영:
   기존 리스크 점수의 Fp 계산에서 law_checks 데이터를 사용하도록 연결.
   violated_count / applicable_count × 100 (각 법령의 risk_weight 가중 적용)
